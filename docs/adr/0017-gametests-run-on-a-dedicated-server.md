# 0017. GameTests run on a dedicated server

Status: Accepted

## Context
The mod said it works on client and server, but nothing ever started a dedicated server with it. The first GameTest run crashed at startup: `BaseSpellBookItem`, `BaseStaffItem` and `OmnitomeItem` assigned `Minecraft.getInstance().player` (a `LocalPlayer`) to an `Entity` variable, and the class verifier loaded `LocalPlayer`, a client class, while the item registry was being built. `RuntimeDistCleaner` refuses that on a dedicated server, so any server with the mod would not start.

## Decision
The GameTests are in the `devtools` source set and run through `runGameTestServer`, which is a dedicated server. Client code that common classes need goes through `ClientItemHooks` with a return type that is a common class (`getLocalPlayerAsEntity` returns `Entity`), so the common class never mentions `LocalPlayer`.

## Consequences
`make gametest` is also the smoke test of the dedicated server side. A client-only class reachable from a registry or a packet fails it at startup. The test template is generated by `scripts/generate-gametest-structure.py` and lives in the devtools resources.
