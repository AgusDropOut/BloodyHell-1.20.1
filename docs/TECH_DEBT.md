## Found by the test world

8. Seven block items have no `#inventory` model: `ancient_torch_block`, `blood_gem_sprout`, `blooddirt_farmland`, `crimson_lure_mushroom_block`, `rhnull_condenser`, `sanguinite_condenser` and `seliora_resting_block`. They are the automatic `BlockItem` that `registerBlock` adds for blocks that have another item (`ancient_torch`, `crimson_lure_mushroom_item`, `blood_gem_sprout_seed`, the two `*_condenser_item`) or none (the farmland and the Seliora block), and none is in a creative tab. The real problem is the condensers: their recipes (`ModRecipes`, built from `block.asItem()`) craft the automatic item, which has no model and no renderer, while the loot table drops the `_item` one. Decide whether to make the recipes output the `_item` (keeping the recipe ids) and to register these blocks with `registerBlockWithoutBlockItem`; both change what recipes, tags and the JEI plugin reference, so check them in game.

Fixed with the test world: null `target` crashes in `UnknownEntityArms` and `SanguineSacrificeEntity`; `CyclopsEntity` and `BlasphemousTwinDaggersCloneEntity` attributes were never registered.
18. Known limitation, not ours: `glowing_crystal_glass_block` and `ancient_blood_capsule` render with the sky color under Rubidium 0.6.5 and Oculus 1.6.4 without shaders, because they need the translucent chunk layer and Rubidium draws it wrong (see ADR 0008). Retest when the pinned Rubidium or Oculus version changes. Fallback if it ever matters: flatten their alpha and use `cutout`.
28. The Omnitome managers and `TaskQueueRenderManager` solve the same problem (run vanilla or GeckoLib drawing at the end of the pipeline) with different shapes: structured tasks with a `MatrixSnapshot` per task against `Runnable` tasks with one capture. See the table of direct managers in `docs/RENDER_ARCHITECTURE.md`.
29. The Omnitome has no void pages in the GUI. `OmnitomeRenderer.renderRecursively` does not draw the page bones, only `OmnitomeVoidLayer` does, and it queues them in `OmnitomeVoidRenderManager`, which draws at `AFTER_LEVEL`. GUI item rendering happens after that stage, so the void pages are drawn in the next frame, before the GUI is drawn over them. In the hand the book is replayed inside `AFTER_LEVEL` by `OmnitomeBookRenderManager` and the void manager runs after it in the same pass, which is why it works there. A fix is to draw the pages immediately in the layer when the context is the GUI, with `bufferSource.getBuffer(ModRenderTypes.getOmnitomeVoid(texture))`. Not applied: it is not required and needs a look at the inventory and hotbar.
30. The staff orbs are not drawn in the GUI (`StaffOrbLayer` skips the GUI context on purpose). The orb shaders raymarch in perspective view space around the orb centre, and in the GUI the pose is in pixel space with an orthographic projection, so the quad and the sphere would not fit. Drawing them there would need an immediate path with its own sphere shader, like the Omnitome void pages in item 29.
31. Accepted as is: `small_blood_sapling` and `giant_blood_sapling` use the `blood_sapling` texture. They had no art of their own and rendered as the missing texture cube. Give them their own textures if that ever matters.
32. GeckoLib 4.8.2 only knows geometry format 1.12.0 and warns for any other version, but it still builds the model. Blockbench exported `the_omnitome` and the three staffs as 1.21.110; their `format_version` was set to 1.12.0 by hand (they use no rotated face UVs, which is what the newer formats add). Export the Bedrock Entity models as 1.12.0, or the warning comes back.
